# 타이핑튠 (TypingTune) 2.0.4

타이핑튠은 Windows에서 한글 입력을 검사하고, 기록으로 확인한 특정 추가 미디어 입력을 선택적으로 차단하는 프로그램입니다. 설치 후 바탕화면의 **타이핑튠 (TypingTune)** 아이콘을 더블클릭하면 진단 화면이 열립니다.

## 설치와 실행

1. `TypingTune-Setup-2.0.4.exe`를 실행합니다.
2. 설치가 끝나면 바탕화면 또는 시작 메뉴에서 타이핑튠을 엽니다.
3. 검사할 키보드와 보정 상태를 확인한 뒤, 예문을 직접 입력합니다.
4. **검사 완료 · 다음**을 누르면 진단 JSON을 Windows의 **다운로드** 폴더에 저장한 뒤 다음 예문으로 넘어갑니다. 원하는 위치에 따로 저장하려면 **진단 JSON 저장**을 사용합니다. LLM에 전달할 때는 `LLM-JSON-GUIDE.md`의 분석 요청문을 함께 사용할 수 있습니다.

지원 대상은 .NET Framework 4.8 이상이 설치된 Windows 10/11이며 앱은 AnyCPU로 빌드합니다. 설치 프로그램은 .NET 설치 여부를 확인하며 시스템 드라이버나 레지스트리 입력기 설정을 바꾸지 않습니다. 관리자 권한을 요청하지 않고 현재 사용자의 `%LOCALAPPDATA%\Programs\TypingTune`에 설치합니다. 다른 설치 폴더를 선택할 수도 있습니다.

**Windows 로그인 시 자동 실행**은 설치 화면에서 선택할 수 있으며 처음에는 선택되어 있지 않습니다. 선택하면 알림 영역에서 시작하고, 바탕화면 아이콘으로 언제든 진단 화면을 열 수 있습니다. **새 설치의 보정은 기본 꺼짐**이며 사용자가 적용할 프로필과 상태를 확인해서 켭니다. 처음 설치한 다른 노트북에 기존 특정 키 규칙을 자동으로 적용하지 않습니다. 이후에는 저장한 보정 설정을 다시 불러옵니다.

## 검사 예문

사전 검사 9개와 자유 입력 1개, 총 10개 선택지를 제공합니다. 각 입력란의 한도는 2,000자입니다.

예문 영역이 문장의 줄 수와 창 너비에 맞춰 세로로 늘어나므로, 예문 안에서 따로 스크롤하지 않고 전체 문장을 볼 수 있습니다. **진단 JSON 안내**와 내용이 넘치는 **보정 설정** 화면은 마우스를 해당 영역에 올린 뒤 휠로 스크롤할 수 있습니다. 스크롤할 때 입력 포커스를 옮기지 않습니다.

| 검사 | 목적 |
| --- | --- |
| 종합 팬그램형 문장 묶음 | 두벌식 A–Z 26개와 Shift 조합 7개를 입력하는 종합 검사 |
| 초성 19개 | 기본 자음과 쌍자음 검사 |
| 중성 21개 | 기본 모음과 복합 모음 검사 |
| 종성 27개 | 받침을 포함한 음절 검사 |
| 겹받침 11개 | ㄳ·ㄵ·ㄶ·ㄺ·ㄻ·ㄼ·ㄽ·ㄾ·ㄿ·ㅀ·ㅄ 검사 |
| 쌍·똑·삶·상 반복 | 비슷한 입력을 연속해서 누를 때 조합이 끊어지는지 검사 |
| 겹받침 자연문장 | 실제 단어와 문장 안에서 겹받침 검사 |
| Shift 집중 | 쌍자음과 ㅒ·ㅖ 조합 검사 |
| 문장 경계와 수정 | 공백·줄바꿈·수정 시 입력 흐름 검사 |
| 자유 입력 | 사용자가 겪는 문제를 재현 |

검사 묶음의 글자 분석으로 계산한 **예상 키 범위**와 이벤트에서 확인한 **실제 관찰 키**를 구분합니다. 예문에 모든 글자 조합이 등장하거나 한 번의 검사로 모든 간헐적 고장을 판별한다고 보장하지 않습니다. 쌍자음처럼 의도적으로 따로 입력한 자모와 문장 중간에 비정상적으로 남은 자모도 구분해서 해석해야 합니다.

영문 자판을 사용하는 노트북에서도 프로그램을 실행할 수 있지만 이 예문의 키 분석은 **표준 한글 두벌식** 기준입니다. 세벌식, 다른 키 배열, 원격 입력 등은 JSON을 분석하는 사람이나 LLM에 검사 조건으로 함께 알려 주세요.

## 검사 완료와 자동 저장

2.0.4부터 **검사 완료 · 다음**을 누르면 파일 선택 창 없이 Windows에 지정된 **다운로드** 폴더에 진단 JSON을 자동 저장합니다. 다운로드 폴더를 다른 드라이브 등으로 옮겼다면 Windows에 등록된 현재 위치를 사용합니다. 저장을 마친 뒤에 입력란을 비우고 다음 예문을 표시합니다. 마지막 예문에서는 파일을 저장하고 현재 예문에 머뭅니다.

저장 파일에는 버튼을 누른 시점의 **현재 검사, 이전 완료 검사, 보관 중인 이벤트, 보정 설정과 상태**가 함께 들어갑니다. 예문 하나의 텍스트만 저장하는 것이 아니므로 같은 세션에서 저장한 여러 파일에는 일부 기록이 겹칠 수 있습니다. 매번 별도 이름을 사용해 기존 파일을 덮어쓰지 않습니다. 저장에 실패하면 다음 예문으로 이동하지 않고 현재 입력과 기록을 유지합니다.

글자가 입력되지 않은 검사도 저장합니다. 입력을 시도했지만 문자가 나오지 않은 상황을 조사할 수 있도록 한 것이며, 빈 결과만으로 정상이라고 판정하지 않습니다. 예문 선택 목록을 바꾸거나 **이전 예문**을 누르는 동작은 자동 저장을 실행하지 않습니다.

**진단 JSON 저장** 버튼은 계속 제공하며 저장 위치를 직접 고를 수 있습니다. 다운로드 폴더의 자동 저장과 수동 저장 모두 로컬 파일 생성입니다. 앱에서 LLM이나 인터넷으로 업로드하지 않습니다.

## 2.0.1의 입력 수집 수정

2.0.1의 기본 진단창은 **저수준 키보드 훅과 IME·UI 이벤트**를 기록하며, Raw Input을 동시에 등록하지 않습니다. 2.0.0의 동시 수집 방식에서 재현된 입력 수집 회귀를 수정한 것입니다. 이번 재현 결과가 모든 Windows 키보드 오류의 원인을 설명한다는 뜻은 아닙니다.

검사 화면에서 선택한 **내장/외장 키보드 이름은 사용자가 기재한 검사 조건**입니다. 개별 이벤트의 물리적 입력 장치를 자동 식별했다는 증거로 사용하지 않습니다. 여러 키보드가 연결되어 있다면 검사마다 사용할 키보드를 하나로 정하고 조건을 기록하세요.

2.0.1~2.0.4 기록에 `native-raw-input` 이벤트가 없는 것은 기본 설계에 따른 결과입니다. 반면 직접 타이핑한 검사에서 IME·UI 이벤트만 있고 `native-hook` 기록도 없다면, 그 파일만으로 물리 키 입력이 정상이라고 판단하지 말고 수집 상태부터 확인해야 합니다.

화면의 키 누름 이벤트 수와 **수집 불완전** 표시, JSON의 `captureHealth`를 함께 확인할 수 있습니다. 이는 진단 근거가 수집됐는지를 확인하는 기능입니다. 키 이벤트가 관찰됐다는 표시가 키보드 정상 판정은 아니며, 기록이 적으면 판단을 보류합니다.

## 종료, 재시작, 알림 영역

입력 초기화 옆의 **강제 종료**와 **프로그램 재시작** 버튼으로 앱을 종료하거나 완전히 종료한 후 다시 시작할 수 있습니다. 다시 시작은 이전 프로세스가 끝난 것을 기다리고 새 프로세스와 새 진단 세션을 사용합니다.

앱의 종료·강제 종료·재시작 기능을 사용하면 기록이 있는 경우 먼저 데이터 폴더의 `recovery` 하위 폴더에 진단 JSON을 자동 보관합니다. 기본 위치는 `%LOCALAPPDATA%\TypingTune\recovery`입니다. 직접 저장한 파일이 있더라도 보관 파일이 추가될 수 있습니다. 자동 보관은 로컬 파일 저장이며 네트워크로 전송하지 않습니다. 필요한 기록은 **진단 JSON 저장**으로 원하는 위치에도 저장할 수 있습니다.

창의 **X 버튼은 진단 기록을 중지하고 화면을 알림 영역으로 숨깁니다.** 보정의 활성화 상태는 유지합니다. 다시 열고 검사를 계속하려면 **기록 시작**을 누릅니다. 알림 영역에는 **입력 진단 열기**, **작동 상태·차단 횟수(이벤트 개수)**, **일시 중지/보정 재개**, **종료** 메뉴가 있습니다. **보정 재개**는 일시 중지를 해제하는 동작이고, 화면의 **프로그램 재시작**은 프로세스를 교체하는 동작입니다. 바탕화면 또는 알림 영역 아이콘을 더블클릭하면 앱이 이미 실행 중이거나 다른 탭을 보고 있더라도 진단 탭이 열립니다.

## 보정 범위

타이핑튠의 보정은 기록으로 확인한 입력 패턴을 대상으로 합니다. 특정 제조사나 모델명에 맞춰 실행을 제한하지 않으며, 각 PC의 실제 진단을 바탕으로 프로필을 선택하고 조정해야 합니다. 특정 문자 주변의 추가 미디어 입력을 억제하는 규칙이 문자 누락, 접점 고장, 모든 IME 오류를 복구하지는 않습니다.

보정 설정의 체크박스는 **추가 신호를 검사할 시간 기준 키**를 선택합니다. 체크한 문자 키 자체는 그대로 전달합니다. 차단 후보는 ‘다음 곡’ 미디어 입력(`vkCode=176`) 중 스캔 코드가 0이고 주입 표시가 있는 신호입니다. 왼쪽 목록은 선택한 키를 뗀 뒤 설정한 시간 안의 신호를, 오른쪽 목록은 선택한 키를 처음 누른 뒤 설정한 시간 안이면서 계속 누르고 있는 동안의 신호를 검사합니다.

진단창의 입력 검사는 보정 체크박스와 별개입니다. 기록 중 검사 입력란에 포커스가 있으면 체크하지 않은 일반 키도 진단 대상이므로, 다른 키의 오류를 찾기 위해 모든 체크박스를 켤 필요는 없습니다.

**목록의 모든 키를 체크하면 이 시간 조건을 시작하는 키가 늘어납니다.** 모든 입력 오류를 자동으로 찾아 고치거나 모든 종류의 키를 차단하는 기능이 되지는 않습니다. 입력 누락·중복·접점 고장에는 별도 진단이 필요합니다. 기준 키를 늘리면 정상적으로 사용한 소프트웨어의 다음 곡 명령도 같은 주입·스캔 코드·시간 조건을 만족할 때 차단될 가능성이 커지므로, 확인된 증상 키부터 적용하고 같은 예문으로 비교하세요.

**기존 증상 프리셋**은 이전 특정 노트북에서 확인한 증상에 맞춰 만든 출발점입니다. 키를 뗀 뒤 `T/O/D/Y/한·영`의 150ms 조건, 처음 누른 뒤 `Q/Backspace`의 30ms 조건을 사용합니다. 노트북 모델을 자동 판별하거나 지금 연결한 키보드에 맞춰 자동 학습한 결과는 아닙니다. 새 설치에서는 이 보정이 꺼져 있고, 업데이트한 기존 설치는 저장한 설정을 사용합니다.

보정은 현재 Windows 세션에서 관찰되는 키 이벤트에 적용하며 **내장 키보드에만 제한하지 않습니다**. 진단 화면의 내장/외장 선택은 검사 조건을 나타낼 뿐, 선택하지 않은 키보드를 보정에서 제외하지 않습니다. 외장 키보드나 다른 프로그램의 주입 입력도 같은 조건을 만족하면 영향을 받을 수 있습니다.

여러 Windows 노트북에서 진단과 설정을 사용할 수 있도록 구성했지만 모든 모델이나 입력 오류에 대한 효과를 보장하지 않습니다. 대상 기기의 키보드와 IME로 직접 입력해서 확인해야 합니다.

차단 기록은 **증상을 줄였다는 근거**이고, 주입 표시가 있는 이벤트만으로 그 신호를 만든 프로그램이나 부품을 특정할 수는 없습니다. 내장 키보드/외장 키보드, 보정 켬/끔을 같은 예문으로 비교하면 원인을 좁히는 데 도움이 됩니다.

## 데이터와 제거

진단은 로컬에서 수행합니다. **검사 완료 · 다음**은 다운로드 폴더에 JSON을 저장하고, **진단 JSON 저장**은 사용자가 선택한 위치에 저장합니다. 외부 서비스에 전달할지는 사용자가 결정합니다. JSON에는 검사창에 입력한 내용이 포함될 수 있으므로 개인정보를 입력하지 않는 예문으로 검사하는 것이 좋습니다. 자세한 범위는 `PRIVACY.md`를 참고하세요.

2.0.3에서 **검사 환경 메모 입력란을 제거**했습니다. 새로 저장하는 진단 JSON에는 `environmentAndUserContext.notes`를 포함하지 않습니다. 이전 버전에서 저장한 JSON이나 복구 파일은 수정하지 않으므로, 기존 파일을 공유할 때는 남아 있는 메모도 확인하세요.

진단 이벤트는 최근 **3,000개**까지 보관하고, 범위를 초과한 이벤트 수를 결과에 표시합니다. 보정의 전역 미디어 이벤트 이력은 별도로 최근 **256개**를 보관합니다. 차단 총계는 보정 모니터 실행 이후 누적이므로 진단 이벤트 보관 수와 다릅니다. 사용자 설정, 실행 상태 및 복구 자료는 기본적으로 `%LOCALAPPDATA%\TypingTune`에 저장합니다.

Windows **설정 → 앱 → 설치된 앱**에서 타이핑튠을 제거할 수 있습니다. 제거 프로그램은 자신이 설치한 파일과 바로가기를 제거하고, 사용자가 저장한 진단 JSON과 사용자 데이터는 보존합니다. 기존 다른 보정 프로그램은 이 설치 프로그램이 자동으로 제거하지 않습니다.
